# 小水滴资料库与监测分析：第一版

## 已接入的内容

小水滴现有两个服务端工具：`analyze_water` 查询登录账号授权范围内的企业、已审批排污口、已审批污染物和监测记录；`search_knowledge` 从经过核对的公共资料中取最多四段内容。资料依据在回答下方展开，国家标准条目附官方链接。资料库数据位于 `src/lib/water-assistant/knowledge.ts`，便于下一轮直接调整条目。

第一版只摘录用户 2026 年 8 月操作说明书中与当前实现一致的操作和 CDC 概念，并加入以下官方来源的适用范围摘要：

| 资料 | 用途 | 官方出处 |
| --- | --- | --- |
| GB/T 14848-2017 地下水质量标准 | 地下水质量评价的标准题录与介质边界 | https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F745E3023BD5B10B9FB5314E0FFB5523 |
| HJ 164-2020 地下水环境监测技术规范 | 点位、采样、分析方法与质控环节 | https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/jcffbz/202012/t20201203_811333.shtml |
| GB 8978-1996 污水综合排放标准 | 污水排放标准的适用范围，需核实行业专门标准等 | https://www.mee.gov.cn/ywgz/fgbz/bz/bzwb/shjbh/swrwpfbz/199801/t19980101_66568.htm |

不把整份用户说明书公开部署：原稿含未实现的物联网自动上传描述，“7 月 12 日至 7 月 19 日为 7 天”按首尾包含计算实际为 8 个自然日。也不把企业审批阈值误称为法定排放限值。

## 实际企业数据的使用

| 数据 | 查询与展示 |
| --- | --- |
| 企业和所属园区 | 企业账号仅查询本人企业；管理员仅查询所属园区企业，服务端再次过滤 |
| 已审批排污口 | 只查询企业 `discharge_outlets.status=approved` 的名称和 ID |
| 已审批污染物 | 查询企业 `pollutant_applications.status=approved` 的名称、单位和当前审批上限 |
| 历史监测记录 | 查询最多 31 个北京时间自然日；按企业、排污口、污染物、单位分组，日均值与异常次数从记录计算 |
| 历史阈值 | 单条记录用当时保存的 `standard_limit` 判断是否超过上限，并与当前审批值并列展示；二者不同则标记复核 |

管理员回答强调园区企业概览和需关注企业；企业回答强调本企业排污口、污染物和记录。图表沿用监测页的 ECharts 折线、配色和交叉提示：每种单位分开绘制北京时间逐日平均值，图中数值来自服务端统计，不由模型造图。无记录显示空状态。管理员概览按**超审批上限记录次数**排序，明确它不是 CDC 风险排名。

## 分析规则与边界

1. 先确定样品是地下水还是污水排放口，并核对企业行业、排放去向、许可证和适用标准，再讨论对应国家标准。平台目前缺少采样介质、完整标准类别、测定方法等字段，不自动套用国标数值。
2. 先看有效监测记录、数值范围、超记录上限的单条记录、缺阈值数量，再看日均值趋势；无数据不能解释为正常。不同单位不共用同一纵轴。
3. 对“异常”只给排查线索：查看采样点位、监测设备与质控记录、排污设施和原始记录。不能从趋势判断污染来源、责任或法定超标。
4. 当前监测数据工具没有计算 CDC。CDC 页面和 Word 报告各自已有计算逻辑；小水滴仅解释 CDC 概念和入口，不根据普通日均值给 CDC 数字。当前阈值模型只支持上限，pH 等上下限指标不能自动作完整达标判定。

## 下一轮可调整

这一版是代码内可编辑的公共资料条目和关键词检索，没有管理员上传、私有资料权限或向量索引。下一轮可增加管理员“上传—预览提取—审核发布—版本管理”的 PDF/DOCX 流程，先按企业/园区权限过滤，再检索片段；并为监测记录补采样介质、标准体系、方法与上下限字段，才考虑自动标准比对。可以增加 CDC 工具，调用与现有页面统一的服务端计算函数，届时再展示 CDC 雷达和风险趋势。
